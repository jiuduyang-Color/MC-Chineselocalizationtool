项目名称： Minecraft 模组一键汉化工具 (MMCT)
项目目标： 为 Minecraft 模组玩家和整合包作者提供一个全自动、高效率的汉化工具，通过调用 AI API，实现从模组文件扫描到汉化资源包生成的全流程自动化。

核心功能需求
工具需提供清晰的命令行菜单界面，支持键盘数字键选择，并包含以下两大核心模式：

一键全自动汉化模式

输入： 用户通过拖拽或输入路径，指定一个 .minecraft 版本文件夹（例如 D:\Games\.minecraft\versions\1.20.1）。

处理： 工具自动定位该文件夹下的 mods 目录。遍历所有 .jar 文件，读取其内的语言文件（如 en_us.json），智能筛选出未包含中文（zh_cn）的模组。

输出： 调用 AI API 翻译这些模组的语言文件，并自动打包成一个符合 Minecraft 资源包（Resource Pack）规范的 .zip 文件。该资源包内的 pack.mcmeta 文件中的 pack_format 值需根据用户选择的游戏版本自动填入。

独立模组文件/目录汉化模式

输入： 用户拖拽或输入路径，指向单个 .jar 模组文件或一个包含多个模组的文件夹。

处理： 对指定的模组文件进行语言文件提取和翻译。

输出： 提供两种选项：

生成独立的汉化资源包。

将翻译好的 zh_cn.json 文件导出到用户指定的目录。

扩展功能与用户定制
为了提升工具的易用性和灵活性，需增加以下定制选项：

资源包自定义：

版本选择： 用户可手动选择资源包对应的游戏版本（如 1.20.1, 1.19.2），工具自动映射到对应的 pack_format 整数值。

元数据编辑： 用户可自定义资源包的描述文本（description）。

图标设置： 用户将 pack.png 图片放入指定文件夹（如 /resource_icon/），工具自动识别、裁剪并缩放为合适尺寸（如 128x128 像素）后打包。

AI 模型与 API 管理：

工具内置一个 config.json 文件，用于保存用户填写的 API Key 和选择的模型。

支持模型： 至少包括 DeepSeek、OpenAI (GPT-3.5/4)、Claude、Gemini。

自动识别： 根据用户填写的 API 基础 URL 和 Key，自动识别并切换模型。

翻译参数配置：

智能提交： 默认启用，工具根据上下文窗口限制，自动计算并分批提交文本，最大化利用 Token。

手动设置： 提供选项让用户自定义每次请求提交的文本行数，工具需设定一个安全阈值（例如 2000 字符或 500 tokens）以防止 API 过载。

国际化支持：

工具需提供两个独立版本：全中文界面（MMCT_ZH.exe）和全英文界面（MMCT_EN.exe）。所有界面文本、提示信息、错误反馈均需完整翻译。

技术选型与代码规范
推荐语言： Go 或 C# (.NET Core)。这两种语言都能编译为无依赖的独立可执行文件，便于分发，且标准库对文件操作、HTTP 请求和 JSON 处理有很好的支持。

代码要求：

代码必须简洁、规范、结构清晰，遵循语言官方推荐的命名和格式标准。

不添加任何冗余注释，代码本身应具有良好的可读性。

严禁“堆屎山”，应合理使用设计模式（如工厂模式创建不同 AI 客户端，策略模式处理不同文件格式），确保代码的可维护性和扩展性。

依赖管理： 所有第三方依赖需在项目文档（README）中清晰列出。

交付前质量检查清单
在最终交付前，请务必对程序进行以下测试，确保所有功能正常工作，无明显 Bug：

路径处理： 测试包含空格、中文、特殊字符的文件夹路径，拖拽和手动输入是否正常。

文件扫描： 确认能正确递归扫描 mods 文件夹，并能准确识别和忽略已含有 zh_cn 语言文件的模组。

API 交互： 测试所有支持的 AI 模型，模拟 API Key 错误、网络超时、返回空值等情况，程序应有清晰的错误提示并优雅降级（不崩溃）。

资源包生成： 验证生成的 .zip 文件结构是否正确，放入游戏后能否被正常识别和应用。测试不同 pack_format 值的正确性。

并发与性能： 确保在处理大量模组时（如 50 个以上），程序界面不卡死，能提供进度反馈。

配置持久化： 测试 config.json 的读写是否正确，修改配置后重启程序能否加载。
